01 · Web application layers

一次註冊分成三層責任

互動流程

HTML

描述內容結構和表單控制項；適當 label 也改善無障礙使用。

CSS

把字款、色彩和版面規則集中，避免每頁重複設定。

Publishing

上載檔案至 web server，檢查相對路徑、首頁、權限與各裝置顯示。

02 · Input validation

Validation 不是只問「有沒有輸入」

檢查例子目的
Presence check電郵不可留空確保必要資料存在
Type／format check日期、電郵格式確保表示方式正確
Range／length check分數 0–100；密碼最少長度確保值在合理界限
Lookup check班別代碼在准許清單確保值屬有效集合
Client 和 server 都要檢查：client-side validation 提供即時回饋；使用者可繞過它，所以 server-side validation 才能保護系統與數據。

03 · State and data

Cookie 保存識別，不應直接保存秘密

Cookie

Browser 按網站保存小量文字，之後隨 request 傳回。可保存 session identifier 或偏好；應設定適當到期、安全與私隱措施。

One-table operation

Server-side script 可按條件 retrieve 或 update 一個資料表。輸入應先驗證，查詢應避免把使用者文字直接拼入指令。

INPUT studentId
IF studentId is valid THEN
    record ← retrieve matching STUDENT row
    DISPLAY selected fields
ELSE
    DISPLAY useful error message
END IF

04 · Original DSE-style practice

活動報名網站：9 分

9 分
原創練習按公開課程範圍設計，並非歷屆試題。
學生在網頁輸入學生編號、電郵及活動代碼。系統檢查後，把報名狀態寫入 REGISTRATION 表，並用 cookie 記住介面語言。

  1. (a) 分別說明 HTML 和 CSS 在此頁的用途。

    [2 分]

    HTML 建立內容／表單結構（1）；CSS 控制版面／一致外觀（1）。

  2. (b) 建議兩項適合的輸入檢查，並指出所檢查欄位。

    [4 分]

    每項合理檢查及對應欄位各 1 分，例如學生編號 presence／format、電郵 format、活動代碼 lookup。

  3. (c) 解釋為何 server 仍須驗證，以及 cookie 不宜保存密碼。

    [3 分]

    Client 檢查可被繞過（1）；server 驗證保護系統／資料（1）；cookie 會存於 client 及隨 request 傳送，直接存密碼有外洩風險（1）。
