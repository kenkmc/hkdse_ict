# 老師網頁管理介面

在現有 Apps Script Web App 網址加上 `?admin=1`，以**部署老師**的校園帳戶登入。這不是公開 GitHub Pages 後台，不需額外註冊或新增資料庫。

正式入口：[老師管理](https://script.google.com/a/macros/jcmkec.edu.hk/s/AKfycbySDrQGZedy7CU0UHJuIVOpimo2cmgGWDla1slXofeN3NU4DWqgxVDmH1dTciuvWRoBhg/exec?admin=1)。學生仍使用同一網址但不加參數。

## 管理範圍

| 畫面 | 對應工作表 | 可做的操作 |
| --- | --- | --- |
| 學生名冊 | Students | 新增、編輯班別／學號／中英文姓名、停用、四欄名冊批量匯入、Google 登入設定及電郵配對修正 |
| 群組管理 | Groups | 新增、改名、設定學年／類型、啟用／停用 |
| 群組成員 | GroupMembers | 新增、按班別批量加入、取消啟用以移出群組 |
| 課業管理 | Assignments | 草稿、開始／截止時間、指示、發佈、封存 |
| 派發對象 | AssignmentTargets | 全體／群組／指定學生，可同時有多個對象 |
| 課業要求 | AssignmentItems | 教材頁面、有效分鐘、課題練習次數、正確率、分層課業、遊戲、模擬考 |
| 班級進度 | TeacherDashboard | 唯讀、手動重新計算已同步摘要、學生紀錄入口 |
| 學習紀錄 | AssignmentProgress、ProgressLatest、TopicProgress、LearningSessions、PageActivity、ExerciseAttempts | 唯讀，搜尋、班別篩選、個別學生查閱、每頁 50 筆 |

學生名冊及進度不會放入 GitHub，不會儲存到管理頁的 localStorage／sessionStorage。介面不載入外部字型、分析服務或第三方 JavaScript。AccountKey 不傳至老師瀏覽器。GoogleEmail 只保存於校方私有名冊，供跨設備配對；詳見 [Google 登入及回復指南](GOOGLE_LOGIN.md)。

## 建立學生及群組

1. 在「學生名冊」新增學生，或從 Excel／Google Sheet 複製四欄：班別、學號、中文姓名、英文姓名，按「貼上名冊」。預覽後確認。
2. 相同班別及學號會拒絕整批匯入（01 與 1 視為相同），不覆蓋原有學生。StudentId 自動建立；學號以文字保存。
3. 先在「Google 登入設定」完成校方 OAuth Client、測試及啟用，學生首次選班別及學號後即時配對，不用啟用碼。如發現誤配，在該學生的「登入配對」填正確電郵或留空解除。未啟用時，學生入口顯示等待老師完成設定，不提供舊啟用碼流程。
4. 在「群組管理」新增例如 `2026 中四 ICT`、`4A`、`中四補底`、`中五拔尖`、`選修 A`。
5. 年級、班別或其他自訂組別選 CUSTOM；程度高／中／低選 LEVEL；選修選 ELECTIVE。學年例：2026-2027。
6. 在「群組成員」批量加入學生，按班別篩選及勾選。每名學生可在多個群組。

升班時可更新同一 StudentId 的班別，另開新學年群組；不重建學生識別碼。停用舊群組會停止向該組派發課業，歷史學習紀錄保留。這不是獨立的歷年名冊快照：紀錄中的 StudentId 會連到現在的名冊資料。

## 派發課業

1. 「課業管理」新增草稿，設定標題、指示及開始／截止時間（香港時間）。
2. 「派發對象」加入一個或多個對象；例如補底群組與個別學生。
3. 「課業要求」選擇課業及要求，設定排序及必須完成與否。
4. 正確率要求填 1–100 的最低百分比；其他要求最低百分比填 0。練習次數及正確率須選課題；有效分鐘可選全站。
5. 分層課業及遊戲只會列出真正有相應功能的課題；模擬考可選卷一、卷二或全部。
6. 返回課業管理改成「已發佈」。缺少對象或要求時不能發佈。
7. 學生重新登入／連接學校後取得最新群組及指定課業；再按「同步至學校」提交完成情況。

修改或移除要求前須轉回草稿，完成後重新發佈。改動要求可能改變下一次計算的完成度；過往完成紀錄並非獨立、不可變的版本化評核證據。需要保留原課業要求時，建議封存舊課業並新建課業。

## 查看進度

「班級進度」按「更新班級摘要」讀取最近已同步資料。點「瀏覽紀錄」後可切換該學生的頁面、時段、練習及課題表現。摘要中的「已同步課業」並不是所有已派發課業；尚未同步者不會被推斷成已完成。

有效操作時間不等於理解程度；閒置或切換分頁不應算作有效學習。同步是學生手動操作，網站未同步或已遺失的本機紀錄，老師不能從 Google Sheet 還原。

## 安全、復原與測試

- 每個讀寫 RPC 都在伺服器核對登入者等於部署老師；單純隱藏按鈕不算權限控制。其他老師暫不支援共同管理；勿改成匿名入口。
- 管理確認碼只保存在瀏覽器記憶體，閒置約 30 分鐘過期，Cache 提前失效時重新載入即可。
- 可編輯欄位及工作表有白名單；保護 StudentId、AccountKey、登入時間等系統欄位。拒絕公式前綴、無效選項／關聯／外站教材 URL。
- 儲存前比對整列版本；舊分頁不能覆蓋其他頁面已儲存的修改。管理寫入與學生同步共用 ScriptLock；直接編輯 Google Sheet 不受這個鎖控制。
- 學生、群組、成員及派發對象採停用，課業採封存，不刪除其歷史紀錄。只有草稿課業的要求可移除，同一管理連線可在 5 分鐘內復原。
- 其他名冊／群組／課業修改需要還原時，使用 Google Sheet「檔案 → 版本紀錄」；先確認要回復的範圍，避免回復整份試算表而丟失後來的學生同步。
- `node scripts/validate_teacher_admin.js`：檢查 13 張表、部署老師權限、個資不外洩、可編輯白名單、批量名冊、關聯、版本衝突、發佈及移除復原。
- 介面已以虛構資料測試 1920×1080、1280×720、390×844 的 13 個畫面、彈窗及匯入／群組選擇。正式校園帳戶的 Google iframe／RPC 端到端仍需部署老師登入驗收；測試沒有改動真實名冊或課業。

## 部署及回復點

2026-10-12（香港時間）已上載並部署為 Apps Script **第 5 版**，API 讀回確認原 deployment 的版本為 5、權限仍是 DOMAIN／USER_DEPLOYING。來源提交 `c290e45`，分支 `feat/phase-1-platform-foundation`；沒有合併 main。11 組驗證通過，正式帳戶的 iframe／RPC 端到端待部署老師驗收；沒有修改真實名冊、群組或課業資料。

上載以下來源（連同既有私密 DeploymentConfig，不把私密設定加入 Git）：

- Code.gs → 雲端「程式碼.gs」
- TeacherAdmin.gs、TeacherResources.gs → 伺服器程式
- TeacherAdminUI.html → HTML 管理介面
- appsscript.json → 保持 DOMAIN、USER_DEPLOYING 及原有兩個 OAuth scopes

修改課程或互動功能後執行 `node scripts/build_teacher_resources.js`；目錄仍以 course_data.js 為唯一來源，功能篩選取自 learning_data.js，避免老師派發不存在的教材／遊戲。

管理介面改動前的程式回復點是 Git commit `6fde48c`、正式 Apps Script **第 4 版**。部署到新版本時維持原 /exec 網址。若需回復：在 Apps Script「部署 → 管理部署」編輯原部署，選回第 4 版。這只回復程式，不會移除學生資料；Git 以非破壞性 revert 回復本次管理介面 commit，勿 reset main 或整份試算表。
