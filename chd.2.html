逐步建立追蹤表開啟流程圖工具
DSE DRY RUN

追蹤時不要跳步

  1. 先寫出初值和資料索引。
  2. 每執行指定語句才更新變數。
  3. 記錄條件 true／false 和所走分支。
  4. 迴圈完成後才寫最終輸出。

01 · Representing algorithms

流程圖與偽代碼表達同一邏輯

流程圖

輸入 score
↓
score ≥ 50?
↙ yes　no ↘
輸出 Pass
輸出 Fail

偽代碼

input score
if score >= 50
    output "Pass"
else
    output "Fail"
兩者均非可執行程式：流程圖強調視覺路徑；偽代碼較易詳細描述資料和步驟。兩者都應保持一致、清晰和無歧義。

02 · Data and interface

數據類型決定可表示的值和可用操作

Integer

整數，例如人數、索引或年份；不保存小數部分。

Real

可表示小數，例如平均值、身高或金額估算。

Character／String

character 保存單一字符；string 保存一串字符，可按索引擷取。

Boolean

保存 true／false，適合條件狀態，例如 valid、found 或 paid。

即時判斷

要保存學生是否已繳交功課，最合適使用哪種數據類型？

選擇答案後會顯示解釋。

03 · Control structures

所有必修算法由三種基本結構組成

不要求巢狀迴圈
→

順序

指令逐步執行。例如輸入半徑、計算面積、輸出結果。

◇

選擇

binary selection 使用兩條路徑；multi-way selection 按多個互斥情況選擇。

↻

迭代

for 適合已知次數；while 適合按條件重複。兩者都要確保可以終止。

Boolean 邏輯

AND 要所有條件成立；OR 只需至少一項成立；NOT 反轉真假。可用 truth table 驗證複合條件。

一維陣列

以同一名稱和索引保存多個同類項目，可載入、輸出、搜尋，以及增加／刪除元素。索引範圍須按題目表示法。

05 · Modularity and revision

模組讓複雜方案可理解、可測試、可重用

清晰責任

每個模組完成一項明確工作，介面說明輸入、輸出和作用。

獨立測試

可先以已知輸入檢查單一模組，再測試整合後的互動。

重用

通用搜尋、驗證或計算模組可在其他方案使用。

規格改變

修改影響集中在相關模組，仍須執行回歸測試確認其他功能。

06 · Original DSE-style practice

分數統計算法：8 分

8 分
原創練習按 D(b) 的 dry run、數據類型及模組化要求編寫。

  1. (a) score 保存 30 個整數分數。指出 score 的合適數據結構及 average 的合適類型。

    [2 分]

    score：一維陣列／列表（1）；average：real（1），因平均值可能有小數。

  2. (b) 追蹤 total←0；for i from 1 to 3：total←total+2*i。寫出每次迭代後 total。

    [3 分]

    i=1：2（1）；i=2：6（1）；i=3：12（1）。

  3. (c) 說明把「計算平均」和「找出最高分」分成兩個模組的兩項好處。

    [2 分]

    每項 1 分：較易理解／獨立測試／除錯／修改／重用。

  4. (d) 條件 0≤score≤100 需要 AND 還是 OR 連接上下限？

    [1 分]

    AND（1），因兩個限制必須同時成立。
