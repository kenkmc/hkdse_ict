01 · Interactive HTML anatomy

HTML 描述內容結構

毋須背誦代碼

點選元素查看功能。HTML 標記讓不同平台的瀏覽器理解內容類型；CSS 一般負責外觀，JavaScript 可提供行為。

index.html · 結構示例
<!doctype html>
<html lang="zh-Hant">
  <head>
    <title>校園開放日</title>
  </head>
  <body>
    <h1>校園開放日</h1>
    <p>歡迎家長和學生參觀。</p>
    <a href="map.html">查看交通地圖</a>
    <img src="hall.jpg" alt="學校禮堂入口">
  </body>
</html>

Element role

跨平台重點：HTML 是公開標準；只要瀏覽器支援相關標準，同一結構可在不同操作系統和裝置呈現。實際外觀仍會受瀏覽器、CSS、字型和屏幕影響。

02 · Information organisation

先安排資訊，再選擇元素

Navigation

導覽與連結

主要選單位置和名稱保持一致；連結文字應描述目的地，並讓使用者知道目前位置。

Table

表格

適合展示需要按列和欄比較的資料；不應純粹用表格堆砌整個頁面版面。

Multimedia

多媒體

圖像、聲音和視像要服務內容目的，並考慮檔案大小、格式支援、字幕和替代資料。

Frame / embed

框架與嵌入

課程提及 frame；現代網站較常以 iframe 嵌入指定內容。須避免令導覽、網址和無障礙使用變得混亂。

資訊層次：首頁先回答網站目的和主要選項；相關內容分組，以標題、段落和留白建立掃讀路徑，不應把所有資訊放在一個長段落。

每日伸展運動

每次使用電腦一段時間後，應離開座位休息、遠望並做適量伸展。

伸展運動示意圖
alt：坐在椅上向上伸展雙手的示意圖

顏色不能是唯一提示

錯誤訊息除紅色外亦應有文字和圖示，照顧色覺差異，也令提示更明確。

一致不等於單調

一致的標題、按鈕和導覽位置可減少學習成本；重點資訊仍可用層次和適量強調突出。

04 · Publish to the Web

由本機檔案到公開網站

01

整理檔案

使用清楚檔名和資料夾，確保圖片、媒體和頁面以可移植的相對路徑連結。

02

本機測試

檢查 HTML、導覽、表格、多媒體、文字和不同屏幕寬度。

03

上載伺服器

把所有必需檔案傳送至 Web 伺服器正確目錄，並設定首頁和所需權限。

04

公開測試

用公開 URL 測試連結、檔名大小寫、媒體載入和不同瀏覽器／裝置。

常見失誤：C:\Users\... 或只在作者電腦存在的絕對路徑，上載後不會自動有效。網站資源通常應按伺服器上的資料夾結構使用相對 URL。

05 · Original DSE-style practice

長者中心活動網站：7 分

7 分
原創練習按課程範圍和公開評核常見指令詞編寫，並非歷屆試題或官方擬題。
長者中心的活動網站使用淺灰色 10 px 文字、只有圖示的選單，活動相片沒有替代文字，而且「交通資料」連結只顯示「按此」。

  1. (a) 建議兩項改善文字和顏色的設計，並解釋對長者的好處。

    [4 分]
    • 增加字體大小（1），令長者／視力較弱使用者較易閱讀（1）。
    • 提高文字與背景的顏色對比（1），令字形較容易分辨（1）。

  2. (b) 說明為選單加文字標籤及為相片加 alt 文字的作用。

    [2 分]
    • 文字標籤清楚說明每個圖示選單的目的地／功能（1）。
    • alt 文字讓屏幕閱讀器傳達相片的資訊或用途，亦在圖片未載入時提供說明（1）。

  3. (c) 把「按此」改成「查看交通資料」有甚麼好處？

    [1 分]

    描述性文字讓使用者在開啟連結前知道目的地／掃讀連結時理解用途（1）。
