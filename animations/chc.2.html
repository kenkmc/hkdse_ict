2.1 傳輸控制協定 / 互聯網協定 (TCP/IP)

解釋數據傳輸的原理：數據如何在網絡中被拆分與重組。

1. 傳輸控制協定 (TCP)

把位元組串流分段，以位元組序號、確認與重傳提供可靠、有序的傳送；接收端重新組合資料。連線無法恢復時仍可能回報失敗。

2. 互聯網協定 (IP)

IP 封包的標頭包含來源及目的地位址；路由器按路由表逐站轉送。IP 本身不保證送達，也不保證一定採用最快路徑。

2.2 互聯網協定 (IP) 位址

32 位元 (32-bit)

IPv4 格式

192.168.1.254

由四組 0-255 的數字組成。因互聯網普及，IPv4 地址已不敷使用。

128 位元 (128-bit)

IPv6 格式

2001:0DB8:AC10:FE01:0000:0000:0000:0001

使用十六進制分組表示，共有 2¹²⁸ 種位元組合，遠多於 IPv4，但並非無限。

2.3 網域名稱系統 (DNS)

因為人類很難記住像 192.0.2.80 這樣的 IP 位址，所以發明了網域名稱系統 (DNS)。它就像互聯網的「電話簿」，負責將人類易讀的域名（Domain Name）轉換為電腦使用的 IP 位址。

2.4 劃一資源定位符 (URL)

URL (Uniform Resource Locator) 就是我們常說的「網址」，用來指示網頁或檔案在互聯網上的確切位置。URL 可包含協定、主機、連接埠、路徑、查詢及片段；預設埠與部分選擇性項目可省略。

2.5 常見網絡協定 (Network Protocols)

HTTP 與 HTTPS 的分別 (加密概念)

Hypertext Transfer Protocol (Secure)

HTTP (明文傳輸)

數據未經加密。若在傳輸過程中被黑客攔截，他們可以直接讀取你的敏感資料（如密碼）。

PWD:123
攔截: PWD:123

HTTPS (加密傳輸)

傳送前會將數據進行加密 (Encryption) 變成亂碼。妥善配置的 TLS 令攔截者難以讀取或竄改傳輸內容，伺服器端再解密；仍須保護端點及檢查證書。

無法解讀: !#@%&*

SMTP / POP3 / IMAP

Email Protocols

電子郵件的運作依賴不同協定分工：
• SMTP：負責將郵件發送到伺服器。
• POP3 / IMAP：負責從郵件伺服器接收/下載電子郵件到使用者的裝置。

寄件人
郵件伺服器
收件人
SMTP (寄出)
IMAP/POP3 (接收)

FTP

File Transfer Protocol

檔案傳輸協定。常用於客戶端與伺服器之間上載或下載大型檔案（例如網頁管理員上傳網站檔案）。

HTTP 狀態信息 (Status Codes)

當瀏覽器請求網頁時，伺服器會傳回狀態碼：

200 OK
請求成功，網頁正常載入。
404 Not Found
客戶端錯誤，找不到請求的網頁。
500 Error
伺服器發生內部意外錯誤。
